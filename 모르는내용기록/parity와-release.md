# CI의 `parity`와 `release`는 뭘 하는 단계인가

> 작성: 2026-11-16 16:05

`ci.yml`에 `parity`와 `release`라는 작업(job)이 새로 생겼습니다.
이름만 봐서는 뭘 하는지 알기 어려워서 정리합니다.

---

## 1. 비유로 먼저 이해하기

배달 시간을 알려주는 계산기를 만들어 파는 회사라고 생각해 봅니다.

### parity = 세 직원에게 같은 문제를 내서 답 맞춰 보기

똑같은 공식을 **Python 직원, Go 직원, Rust 직원** 세 명에게 나눠 줬습니다.
손님을 받기 전에 시험을 봅니다.

> "3km 거리에 주문 2건 밀려 있으면 몇 분 걸려요?"

- Python 직원: 19.5분
- Go 직원: 19.5분
- Rust 직원: 19.5분

(숫자는 설명을 위한 예시입니다.)

세 명이 **모두 같으면 통과**입니다.
한 명이라도 다르게 답하면 공식을 잘못 옮겨 적은 사람이 있다는 뜻이라 **가게 문을 열지 않습니다(배포 중단).**
이런 문제 23개를 자동으로 풀게 하는 게 `parity`입니다.

### release = 그 버전의 공식을 금고에 넣어 두기

시험을 통과하면 오늘 쓴 **공식(모델 파일)** 과 **성적표(성능 기록)** 를
"v1.0"이라고 적힌 상자에 넣어 **금고(GitHub Release)** 에 보관합니다.
나중에 "v1.0 때는 어떤 공식을 썼더라?" 하면 금고에서 꺼내 보면 됩니다.

### 한 줄 정리

| 작업 | 한 줄 설명 |
| --- | --- |
| **parity** | 세 언어 서버가 **같은 답**을 내는지 시험 |
| **release** | 시험을 통과한 모델 파일을 **버전 이름으로 보관** |

---

## 2. 조금 더 자세히: parity

parity는 영어로 **"동등함, 같음"** 이라는 뜻입니다.

### 왜 필요한가

이 프로젝트에는 같은 모델로 배달 시간을 예측하는 서버가 세 개 있습니다.

| 서버 | 언어 | 사용하는 모델 |
| --- | --- | --- |
| `api/` | Python | 학습한 **원본** 모델 (scikit-learn) |
| `api-go/` | Go | 같은 모델을 **ONNX로 바꾼** 파일 |
| `api-rust/` | Rust | 같은 모델을 **ONNX로 바꾼** 파일 |

같은 모델이니 같은 답을 내야 합니다.
하지만 ONNX로 **변환하는 과정**이나 **언어마다 다른 계산 방식** 때문에 답이 달라질 수 있습니다.
이걸 배포 전에 잡아내는 단계입니다.

### 어떻게 동작하나

1. 세 서버를 동시에 띄웁니다.

   | 서버 | 내 컴퓨터(CI) 포트 |
   | --- | --- |
   | Python | 8080 |
   | Go | 8081 |
   | Rust | 8082 |

2. `training/check_parity.py`가 **같은 입력 23건**을 세 서버의 `POST /eta`에 보냅니다.
   - 고정 입력 3건: `(3km, 2건)`, `(0km, 0건)`, `(8km, 10건)`
   - 무작위 입력 20건: 거리 0.5~8km, 주문 0~10건 (seed 0이라 매번 같은 값)
3. **Python 서버의 답을 정답**으로 보고 Go·Rust 서버의 답과 비교합니다.
4. 차이가 **0.0001분 미만**이면 `PASS`, 하나라도 넘으면 `FAIL`.
   `FAIL`이면 스크립트가 `exit 1`로 끝나서 **CI가 멈추고 배포도 되지 않습니다.**

> Python 서버는 반드시 원본 모델(`MODEL_IMPL=sklearn`)로 띄워야 합니다.
> ONNX끼리 비교하면 변환 과정의 실수를 잡을 수 없기 때문입니다.
> 스크립트가 `/health`에서 모델 이름을 먼저 확인합니다.

## 3. 조금 더 자세히: release

### 어떤 파일을 올리나

`v1.0` 같은 태그를 올리면 GitHub의 **Releases** 페이지에 `v1.0` 항목을 만들고 아래 파일을 첨부합니다.

| 파일 | 내용 |
| --- | --- |
| `model_sklearn.onnx` | scikit-learn 모델 |
| `model_dl.onnx` | PyTorch 신경망 모델 |
| `metrics_sklearn.json` | scikit-learn 모델의 성능 기록(오차 등) |
| `metrics_dl.json` | 신경망 모델의 성능 기록 |

### 왜 필요한가

학습 결과물(`artifacts/`)은 **git에 커밋하지 않습니다.**
CI가 만든 결과물은 Actions에 잠깐 남았다가 **일정 기간이 지나면 지워집니다.**
Release에 올려 두면 **계속 남습니다.**

그래서 `v1.0` 하나로 세 가지를 모두 찾을 수 있습니다.

| 무엇 | 어디에 |
| --- | --- |
| 코드 | git 태그 `v1.0` |
| 서버 이미지 | `ghcr.io/.../eta-api:v1.0` (Go·Rust도 같은 태그) |
| 모델 파일 | GitHub Release `v1.0` |

### 권한

Release를 만들려면 저장소에 **쓰기 권한**이 필요합니다.
그래서 `release` 작업에만 `permissions: contents: write`를 따로 줬습니다.
다른 작업은 읽기 권한만 가집니다.

## 4. 그런데 Go·Rust 서버는 왜 만들었나

이 프로젝트에서 Go·Rust가 **꼭 필요해서** 만든 것은 아닙니다.
실제로 Render에 배포되는 것도 Python 서버(`eta-api`) 하나뿐이고, Go·Rust는 이미지만 만들어 둔 상태입니다.
MLOps의 중요한 개념 하나를 **직접 확인해 보려는 연습**입니다.

### 확인하려는 것: "모델은 Python으로 학습해도, 어디서든 쓸 수 있다"

모델을 **ONNX 파일**로 바꿔 두면 Python 없이 **다른 언어에서도** 그 모델을 실행할 수 있습니다.
이 프로젝트는 그걸 Go와 Rust로 실제로 해 보고, `parity`로 결과가 정말 같은지 검사합니다.

> 비유: 요리법(모델)을 한국어로 썼지만 **표준 양식(ONNX)** 으로 옮겨 두면,
> 다른 나라 주방(Go, Rust)에서도 같은 맛을 낼 수 있는지 시험해 보는 것입니다.

### 실제 회사에서 이렇게 하는 이유

| 이유 | 설명 |
| --- | --- |
| **서버가 이미 다른 언어로 되어 있을 때** | 회사 백엔드가 Go나 Java로 되어 있으면, 모델 하나 쓰려고 Python 서버를 따로 두기보다 기존 서버에 ONNX 파일만 넣는 편이 간단합니다. |
| **빠르고 가볍게 돌려야 할 때** | Go·Rust는 Python보다 메모리를 적게 쓰고 응답이 빠르고, 이미지 크기도 작습니다. 요청이 아주 많은 서비스에서 차이가 납니다. |
| **역할 분리** | 데이터 과학자는 익숙한 Python으로 **학습**하고, 서비스 개발자는 자기 언어로 **서빙**합니다. 둘 사이를 ONNX 파일 하나로 주고받습니다. |
| **기기 안에서 실행할 때** | 휴대폰 앱이나 작은 장비처럼 Python을 넣기 어려운 곳에서도 ONNX Runtime이 있으면 모델을 돌릴 수 있습니다. |

### 이때 생기는 위험 → 그래서 parity

언어가 바뀌면 같은 모델이라도 **답이 조금씩 달라질 수 있습니다.**

- ONNX로 변환할 때 생기는 아주 작은 오차
- 입력을 숫자로 바꾸는 방식의 차이 (예: 정수를 소수로 바꾸는 방법)
- 잘못된 입력을 처리하는 방식의 차이 (Rust에서 `NaN` 처리를 따로 만든 이유이기도 합니다)

이 위험을 자동으로 잡는 장치가 `parity`입니다.
그래서 **Go·Rust를 만든 것과 `parity`를 만든 것은 한 세트**입니다.

## 5. 전체 순서에서의 위치

```
test → train → parity ─┬→ image → deploy
(테스트) (학습·검증) (세 언어 비교)  │  (이미지 빌드)  (서버 배포)
                       └→ release
                          (모델 보관)
```

- `parity`를 **통과해야** `image`와 `release`가 돕니다. (`needs: parity`)
- `image`, `release`, `deploy`는 **`v`로 시작하는 태그**를 올릴 때만 돕니다.
  `main`에 푸시할 때는 `parity`까지만 돕니다.
