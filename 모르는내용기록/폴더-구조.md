# 프로젝트 폴더 구조 한눈에 보기

> 작성: 2026-11-16 15:16
> 기준: `main` 브랜치 (마지막 커밋 `3cb08a0`) + 아직 커밋하지 않은 `api-rust/`

이 저장소는 **배달 예상 시간(ETA)을 알려주는 API**입니다.
같은 API를 **Python · Go · Rust** 세 언어로 만들어 두었고,
예측에 쓰는 모델은 **Python으로 학습**한 뒤 **ONNX 파일**로 바꿔서 세 서비스가 함께 씁니다.

```
학습(training/) ──► 모델 파일(artifacts/) ──► 서빙(api/, api-go/, api-rust/)
```

## 2. 폴더별 역할

### `api/` — Python API 서버

[api/app.py](../api/app.py)가 서버 본체입니다. 주소는 세 개입니다.

| 주소 | 하는 일 |
|---|---|
| `GET /` | API 소개 HTML 페이지 |
| `GET /health` | 서버가 살아 있는지 확인 → `{"status":"ok","model":"..."}` |
| `POST /eta` | 거리·대기 주문 수를 받아 예상 시간(분) 계산 |

**예측 방법은 환경 변수 `MODEL_IMPL`로 고릅니다.**
`app.py`는 `api/predictors/{MODEL_IMPL}.py`를 불러와서 그 안의
`estimate_delivery_minutes` 함수를 씁니다.

| `MODEL_IMPL` | 불러오는 파일 | 필요한 모델 파일 |
|---|---|---|
| `rule` (기본값) | `predictors/rule.py` | 없음 (공식: 10분 + 3분/km + 2분/주문) |
| `sklearn` | `predictors/sklearn.py` | `artifacts/sklearn.joblib` |
| `dl` | `predictors/dl.py` | `artifacts/dl.pt` |
| `onnx` | `predictors/onnx.py` | `artifacts/model_sklearn.onnx` |

```powershell
$env:MODEL_IMPL = "sklearn"; uv run uvicorn api.app:app --port 8080
```

> 비유: `app.py`는 **계산대**, `predictors/`는 **계산기 서랍**입니다.
> 계산대는 그대로 두고 서랍에서 어떤 계산기를 꺼낼지만 `MODEL_IMPL`로 정합니다.

### `training/` — 모델 만들기

순서대로 실행하면 `artifacts/`에 모델이 생깁니다. CI도 이 순서 그대로 실행합니다.

```
data.py ──► train_sklearn.py ──► validate_model.py sklearn
        └─► train_dl.py      ──► validate_model.py dl
                                        │
                                        ▼
                                 export_onnx.py  (→ model_*.onnx)
```

- **validate_model.py**: "규칙(rule)보다 덜 틀리는가?" + "평균 오차 2분 미만인가?"
  둘 중 하나라도 실패하면 CI가 멈춰서 배포되지 않습니다.
- **check_parity.py**: 테스트(pytest)가 아니라 **서버 세 개를 모두 띄운 뒤** 실행하는 비교 스크립트입니다.
  기준은 `MODEL_IMPL=sklearn`으로 띄운 Python 서버입니다.

실행은 `python -m` 방식으로 합니다 → [python-m-실행방식.md](python-m-실행방식.md)

### `artifacts/` — 학습 결과물

**git에 올리지 않습니다** (`.gitignore`에 `artifacts/`).
새로 clone하면 이 폴더가 없으니 `training/` 스크립트를 먼저 돌려야 합니다.

`model_sklearn.onnx`가 가장 중요합니다. Python(`onnx`), Go, Rust 서비스가 모두
이 파일 하나를 읽습니다. 그래서 세 언어의 예측 결과가 같아야 정상입니다.

### `api-go/`, `api-rust/` — 같은 API를 다른 언어로

`api/app.py`와 **똑같은 계약**(같은 주소, 같은 요청·응답 모양, 잘못된 입력에는 같은 422 오류)을
Go와 Rust로 다시 만든 것입니다. 둘 다 ONNX 모델만 쓰므로 `/health`의 `model`은 항상 `"onnx"`입니다.

| 언어 | 서버·주소·입력 검증 | 모델 실행 | 테스트 |
|---|---|---|---|
| Python | `app.py` | `predictors/onnx.py` | `tests/` |
| Go | `main.go` + `handler.go` | `predictor.go` | `handler_test.go` |
| Rust | `main.rs` + `eta.rs` (+ `json.rs`) | `predictor.rs` | `eta.rs`, `json.rs` 안의 `#[test]` |

Rust에만 `json.rs`가 따로 있는 이유: Python은 `NaN`, `Infinity`를 JSON 숫자로 받아 준 뒤
422로 거절하는데, Rust의 표준 JSON 라이브러리는 이걸 아예 형식 오류로 처리합니다.
오류 응답까지 Python과 똑같이 맞추려고 파서를 직접 만들었습니다.

## 3. 모델 파일은 어떻게 Docker 안으로 들어가나

| 서비스 | Dockerfile | 이미지에 넣는 것 |
|---|---|---|
| Python | `api/Dockerfile` | `api/` 코드만. 기본 `MODEL_IMPL=rule` 이라 모델 파일 불필요 |
| Go | `api-go/Dockerfile` | Go 실행 파일 + ONNX Runtime + `artifacts/model_sklearn.onnx` |
| Rust | `api-rust/Dockerfile` | Rust 실행 파일 + ONNX Runtime + `artifacts/model_sklearn.onnx` |

세 Dockerfile 모두 **저장소 루트(`.`)를 빌드 컨텍스트**로 씁니다.
그래서 `api-go/` 안에서가 아니라 루트에서 `-f`로 파일을 지정해 빌드합니다.

```powershell
docker build -f api-go/Dockerfile   -t eta-api-go   .
docker build -f api-rust/Dockerfile -t eta-api-rust .
```

Go·Rust 이미지는 ONNX Runtime 버전을 `uv.lock`의 `onnxruntime` 버전에 맞춥니다.
Python과 같은 런타임을 써야 예측 값이 소수점까지 같기 때문입니다.

## 4. 로컬에서 세 서버 동시에 띄우기 (포트 정리)

세 서버 모두 **컨테이너 안에서는 8080**을 씁니다. 바깥(내 PC) 포트만 다르게 연결합니다.

| 서비스 | 실행 방법 | 내 PC 포트 |
|---|---|---|
| Python | `uv run uvicorn api.app:app --port 8080` | 8080 |
| Go | `docker run -d --rm --name eta-go   -p 8081:8080 eta-api-go` | 8081 |
| Rust | `docker run -d --rm --name eta-rust -p 8082:8080 eta-api-rust` | 8082 |

```powershell
uv run python -m training.check_parity   # 세 서버 결과 비교
```

자주 하는 실수 두 가지:

- `-p 8081:80` ✗ → 앱이 컨테이너 안의 **8080**에서 열리므로 `-p 8081:8080` ✓
- 같은 `--name`으로 다시 `docker run` → "name is already in use" 오류.
  먼저 `docker rm -f eta-go`로 기존 컨테이너를 지웁니다.

포트 개념 자체는 → [로컬서버-주소와-포트.md](로컬서버-주소와-포트.md)

## 5. 루트에 있는 설정 파일들

| 파일 | 한 줄 설명 |
|---|---|
| `pyproject.toml` | Python 의존성. 기본(서버용) / `dev`(pytest) / `train`(학습 라이브러리) 세 그룹 |
| `uv.lock` | 위 의존성의 정확한 버전. 직접 고치지 않고 `uv`가 관리 |
| `.github/workflows/ci.yml` | PR·`main` push 때 테스트 → 학습·검증·ONNX 변환, `v*` 태그면 이미지 배포 + Render 배포까지 |
| `AGENT.md` | 테스트 작성 규칙 |
| `.gitignore` | `.venv`, `__pycache__`, `artifacts/` 등 git 제외 목록 |
| `.dockerignore` | Docker 빌드 때 제외 목록 |
| `.vscode/settings.json` | VS Code 테스트 탭에서 pytest 사용 |

`uv run --group train ...`처럼 `--group train`을 붙여야 학습 라이브러리(scikit-learn, skl2onnx 등)가
설치됩니다. 서버 이미지에는 `train` 그룹이 들어가지 않아 이미지가 가볍습니다.
