# v1.0 태그를 만들고 릴리스까지 확인한 과정

> 작성: 2026-11-16 15:51
> 기준 커밋: `3bd0b9b` (태그 `v1.0`), CI 실행 번호 `43818563683`

`ci.yml`을 정리하고, 교차 런타임 일치 테스트(`parity`)와 모델 릴리스(`release`) 작업을 넣은 뒤
**`v1.0` 태그 하나로 테스트 → 학습 → 검증 → 이미지 → 릴리스 → 배포**가 자동으로 끝나는 것까지 확인한 기록입니다.

## 1. 태그 전에 한 일: `ci.yml` 정리

### 들여쓰기 맞추기

| 위치 | 문제 | 고친 내용 |
| --- | --- | --- |
| `image` 작업의 Python·Go·Rust 단계 | 다른 단계는 6칸(`      - `)인데 4칸으로 들어가 있었음 | 6칸으로 맞춤 |
| Rust 단계의 `with:` | 너무 깊게 들여써져 있고 앞에 빈 줄이 있었음 | 위치를 맞추고 빈 줄 삭제 |
| Python API 단계 | 새 onnx 단계 사이에 기존 rule 단계가 끼어 있고, `APP_VERSION`·`tags` 줄이 떨어져 나와 있었음 | 떨어진 줄을 onnx 단계 안으로 합치고, 같은 태그를 덮어쓰던 rule 단계는 삭제 |
| `parity` 작업 | 0칸에 있어서 `jobs:` **밖**에 있었음 | 2칸 들여써서 `jobs:` 안으로 옮김 |

> `v0.2.1` 때 `deploy`가 `jobs:` 밖에 있던 것과 같은 실수입니다.
> **YAML은 들여쓰기가 곧 문법**이라서, job 이름(`parity:`)은 반드시 `jobs:` 아래 **2칸**, 단계(`- name:`)는 `steps:` 아래 **6칸**이어야 합니다.

고친 뒤 YAML이 제대로 읽히는지 파이썬으로 확인했습니다.

```bash
uv run --no-project --with pyyaml python -c "import yaml; d=yaml.safe_load(open('.github/workflows/ci.yml', encoding='utf-8')); print(list(d['jobs']))"
# ['test', 'image', 'deploy', 'train', 'parity', 'release']
```

## 2. 지금의 CI 흐름

```
                     ┌─→ image (Python·Go·Rust 이미지 → ghcr.io) ─→ deploy (Render)
test → train → parity┤
                     └─→ release (GitHub Release 에 모델 첨부)
```

- `main`에 푸시하면 `test → train → parity`까지만 돕니다.
- `v`로 시작하는 **태그**를 푸시하면 `image`, `release`, `deploy`까지 전부 돕니다.
  (`if: startsWith(github.ref, 'refs/tags/v')` 조건 때문)
- 그 결과 **코드(태그) · 이미지(GHCR) · 모델(Release)** 이 모두 같은 이름 `v1.0`으로 묶입니다.

## 3. 태그를 만든 순서

### ① 같은 이름의 태그가 이미 있는지 확인

```bash
git tag -l                     # 내 컴퓨터(로컬)의 태그 목록
git ls-remote --tags origin    # GitHub(원격)의 태그 목록
git status --short             # 커밋 안 한 변경이 없는지
```

`v0.1`, `v0.2`, `v0.2.1`만 있고 `v1.0`은 없었습니다. 같은 이름 태그가 이미 있으면 푸시가 거절되니 먼저 확인합니다.

### ② 태그 만들기

```bash
git tag -a v1.0 -m "v1.0" 3bd0b9b
```

| 부분 | 뜻 |
| --- | --- |
| `-a` | **주석 태그(annotated tag)**. 만든 사람·날짜·메시지가 같이 저장됩니다. `-a` 없이 만들면 이름만 있는 가벼운 태그가 됩니다. |
| `-m "v1.0"` | 태그 메시지 |
| `3bd0b9b` | 태그를 붙일 커밋. 생략하면 지금 커밋(HEAD)에 붙습니다. |

### ③ 태그 푸시

```bash
git push origin v1.0
```

> `git push`만 하면 **태그는 올라가지 않습니다.** 태그는 이렇게 이름을 따로 적어서 올려야 합니다.

## 6. 이번에 배운 핵심

- **태그 = 배포 버튼.** 이 프로젝트는 `v*` 태그를 올릴 때만 이미지 빌드·릴리스·배포가 돕니다.
- **태그는 따로 푸시한다.** `git push origin <태그이름>`.
- **검증 게이트는 `needs:`로 건다.** `image`와 `release`가 `needs: parity`이므로 세 언어의 예측이 다르면 배포도 릴리스도 일어나지 않습니다.
- **권한은 필요한 작업에만 준다.** `release` 작업에만 `permissions: contents: write`를 줬습니다.
- **버전 하나로 묶는다.** 같은 `v1.0`으로 소스 코드, Docker 이미지, 모델 파일을 모두 찾을 수 있습니다.
