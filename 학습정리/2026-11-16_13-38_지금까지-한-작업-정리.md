CI `train` 작업의 순서:

```
학습(sklearn) → 검증(sklearn) → 학습(dl) → 검증(dl) → ONNX 변환 + 일치 확인 → 결과물 업로드
```

로컬에서 돌린 결과:

```
sklearn 평균 오차 1.18분  (기준선 rule 11.57분)  → PASS
dl      평균 오차 1.18분  (기준선 rule 11.57분)  → PASS
model_sklearn.onnx: 원본 vs ONNX 최대 오차 7.63e-06 OK
model_dl.onnx:      원본 vs ONNX 최대 오차 0.00e+00 OK
```

**이날 배운 핵심**
- **재현 가능한 학습**: 같은 seed, 같은 코드, `uv.lock`으로 고정한 같은 라이브러리 버전을 쓰면 누가 돌려도 같은 모델이 나옵니다.
- **검증 게이트**: 프로그램이 `exit 1`로 끝나면 GitHub Actions는 그 단계를 실패로 보고 멈춥니다.
- **정규화를 모델 안에 넣기**: `StandardScaler`, `WithNormalize`처럼 정규화를 모델에 포함하면 서빙할 때 따로 계산할 필요가 없습니다(학습과 서빙의 차이 방지).
- **ONNX**: 학습한 프레임워크(sklearn, PyTorch)와 상관없이 같은 형식으로 저장하는 모델 파일입니다. `onnxruntime`만 있으면 실행할 수 있어서 서버가 가벼워집니다.
- **학습 결과물은 커밋하지 않는다**: `artifacts/` 폴더는 `.gitignore`에 넣었습니다. CI가 매번 새로 만들고 Actions의 Artifacts(`model-artifacts`)로 내려받을 수 있습니다.
- **dependency group**: `dev`(테스트용), `train`(학습용)처럼 용도별로 라이브러리를 나누면 배포용 Docker 이미지에는 필요한 것만 들어갑니다.

| 상황 | 원인 | 해결 |
| --- | --- | --- |
| `git push` 하니 `no upstream branch` 오류 | 로컬 `main`이 GitHub의 `main`과 짝지어지지 않음 | `git push -u origin main`으로 한 번 연결 (자세한 내용: `모르는내용기록/git-push-업스트림.md`) |
| `ci.yml`만 올리려고 함 | 새 `train` 작업이 `training/`, `pyproject.toml`의 train 그룹을 쓰는데 그 파일들이 커밋되지 않음 | 관련 파일을 한 커밋으로 같이 올림 |
| `ci.yml`에서 `APP_VERSION` 줄이 사라져 있었음 | 수정하다 실수로 지움. 그대로면 배포 서버의 버전이 항상 `dev`로 표시됨 | 원래대로 되살림 |
| Render `deploy`가 동작 위치가 이상함 | YAML 들여쓰기 오류로 `jobs:` 밖에 있었음 | `be93e6d`에서 들여쓰기 수정 |
